- (decision) New PRD is for an internal guild loot-distribution app administered by the owner and consultable by raiders; allocation rules vary by loot type and consider attendance, DPS Warcraft Logs performance, and prior loot, with loot tables, roster loot status, and ratios; user wants a capability-first product that can be filled out over time and ideally imported into Google Sheets.
- (decision) User supplied a loot-allocation flowchart as a source of current rules; Google Sheets output should share each raider's ratios, impact-priority rank, BiS/impact/alt-BiS item classification, and simmed impact gain by class/spec to make in-raid decisions transparent. Flowchart interpretation is provisional pending confirmation.
- (decision) Confirmed allocation rules: normal items exclude tier set, BiS, and impact; tier-set rolls follow MT1 then MT2 tank priority; +2 means a spec for which an item is BiS has priority over a spec for which it is not, with the ratio updated; impact-item eligible classes are configurable; Warcraft Logs parse is DPS-only; gain is percent DPS/HPS increase with flat increase as tie-break, while tank impact metric is configurable; ratio resets to zero three weeks after a new raid tier releases. MT2 is the second tank priority after MT1.
- (decision) Further confirmed: if no candidate has an item as BiS, interested raiders roll without ratio impact; BiS assignments are configured by the owner each phase, potentially using sources such as wowtbc.gg; missing DPS parse is 1; Presence max is the number of raid opportunities (e.g. 10 for 8 attended out of 10 possible); tanks have no impact metric because they have priority across their loot table; impact-loot count does not reset, only BiS ratio resets; impact score uses gain as a factor and an identical whole score is resolved by roll; tier sets differ from class-bound items but are treated similarly. Product should have a graphical interface for setup and save locally in a JSON file.
- (decision) Confirmed: BiS items cannot be passed; the item is awarded to the eligible raider and impacts their ratio. Tier sets and class-bound items are awarded by roll among eligible classes after tank priority. For v1, user is open to doing everything through Google Sheets; preferred eventual surface is a desktop app to avoid hosting costs. Google CLASP was suggested as an implementation aid, not a product requirement.
- (decision) User confirmed the synthesized product vision is accurate for the MVP: configure phases, roster, item categories, and rules; apply them during loot distribution; record awards; and let raiders consult transparent ratios, rankings, item status, and simmed gains. Google Sheets is acceptable for v1; local desktop GUI remains preferred direction.
- (decision) Core Sheets MVP capability shape: roster tab with raider name, role, attendance/presence, bench counts, and BiS ratio; impact-items tab ordered by attribution priority with inspectable score details (gain, Warcraft Logs parse, and other components); per-spec BiS tab with item slots as columns, visible to raiders.
- (decision) User described a possible Lua raid addon workflow: ask the officer to classify a dropped item as BiS, non-BiS, impact, or tier set; export award results as JSON for Sheets to ingest and update automatically; also receive JSON so ratios can be displayed live. Gargul may need a small Lua tweak. This is an implementation direction to scope, not yet a confirmed MVP commitment.
- (decision) Confirmed MVP integration: the officer alone uses an enhanced Lua/Gargul interface; raiders keep the default Gargul interface and install nothing extra. The officer manually awards loot. The enhanced window displays roll type, score, and live ratio; a BiS award has an Impact checkbox so it can be recorded as impact instead. Import state before each raid; update scoring live during the raid; export accumulated awards after the raid for Sheets to update roster ratios and scores.
- (decision) Confirmed v1 data inputs: roster, impact loot definitions, parses, and per-phase BiS lists are manually entered in Sheets; attendance is automatically processed from a Warcraft Logs raid link; bench is entered manually; ratios and scores are updated from Gargul JSON exports. Automatic retrieval of Warcraft Logs parses or BiS lists is a later iteration, not MVP.
- (decision) User paused discovery and confirmed the tool is for one persistent WoW roster across phases. Continue later; preserve the current draft state and leave remaining questions open rather than finalizing.
- (change) Clarified raid-night division of responsibility: owner keeps Google Sheets open on a second screen to identify whether a drop is BiS, Impact, etc.; the in-game Lua/Gargul enhancement has no item-type knowledge and must not classify items. It is limited to displaying and handling live BiS ratios and Impact Scores, simplifying Lua development. Any category-related treatment is provided explicitly by the owner, not inferred by the addon.
- (change) Clarified operator workflow: the enhanced Gargul remains the loot-distribution interface and exposes its roll value; it also displays the BiS ratio and Impact Score. The owner checks the Sheet's item classification and decides whether the ratio, score, or roll value governs the award. The addon does not classify items or select which signal applies.
- (decision) Confirmed product scope: one persistent roster for WoW across tiers, with one raid tier active at a time.
- (decision) Clarified Presence formula: Presence is raw attended raids plus bench appearances; Presence max is possible raids. Both BiS Ratio and Impact Score use normalized Presence = Presence / Presence max. BiS Ratio = normalized Presence / (BiS loots received + 1); Impact Score uses normalized Presence multiplied by DPS parse and simmed gain, divided by (Impact Items received + 1).
- (decision) Confirmed tier transition: completed-tier data can be archived for reference. BiS Ratio resets three weeks into the new tier. Impact-loot scoring state may or may not carry over; user wants the option to retain it because the reset policy is undecided.
- (decision) Confirmed JSON import behavior: do not add duplicate-upload checks or correction reconciliation. Owner ensures each raid is uploaded once and edits the JSON manually if an award needs correction.
- (decision) Confirmed Warcraft Logs attendance mismatch behavior: ignore participants that cannot be matched to roster members; owner makes any needed correction in the JSON or roster list.
- (decision) Confirmed MVP success and raid loop: before raid, export current Sheets data as JSON and load it into Gargul; during raid, inspect each interested raider's BiS/non-BiS roll type and roll value alongside BiS ratio or Impact Score, manually award loot using the Sheet classification, and see live state updates affect subsequent rolls; after raid, export all attributions from Gargul and import to Sheets. Success means no bugs in live ratio/score updates or JSON import/export and clear Sheets data.
- (decision) Confirmed Google Sheets permissions: all Raiders have view-only access to all three shared tabs; editing is restricted to the owner.
- (decision) Confirmed completed-tier archives are for reference only: archived data is read-only and cannot be restored into an active tier.
- (override) Overrides to early discovery notes: simmed gain is part of Impact Score and identical complete scores resolve by roll; tanks use table-wide priority and no Impact Score; Impact Item Count carryover is owner-configurable at tier transitions; the addon does not classify item types and Sheets determines which ratio/score/roll to consider; BiS Ratio resets three weeks after the new tier begins.
- (override) Final allocation clarification: do not model officer-approved class-priority exceptions; any rare exception is handled manually during the raid. If a BiS drop is marked Impact in Gargul, leave BiS Ratio unchanged and update only Impact Score/Impact Item Count.
- (decision) Confirmed BiS candidate ordering: any BiS-eligible Raider rolling has priority over all non-BiS rollers, regardless of ratio. Rank BiS candidates by BiS Ratio; exact ratio ties are decided manually using Gargul's roll value. Include alt-BiS item status in the raider-facing per-spec Sheets view.
- (decision) Confirmed edge behavior: initialize Presence Max to 1 before raid activity so Presence 0 yields Normalized Presence 0 and equal starting ratios; malformed JSON imports are rejected without changing existing data. Duplicate-upload detection remains out of scope and is handled by the owner.
- (decision) Clarified the three-week BiS reset: reset the BiS-loot count and the attendance baseline, as a new beginning; retain the prior tier history for archive/reference. Scope of attendance reset for Impact Score remains to clarify.
- (decision) Confirmed attendance windows are separate: the BiS Ratio uses attendance and BiS-loot count accumulated since its three-week reset; the Impact Score continues using attendance across the full active tier, regardless of the BiS reset. Impact Item Count carryover is independently configurable.
